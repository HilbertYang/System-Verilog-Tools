Question: Sequence Detector — "1001" (Overlapping)

Design a Moore FSM named seq_detection_1001 that detects the bit pattern
"1001" in a serial input stream, with overlapping matches allowed.

Ports:
  Inputs : clk (posedge), rst_n (active-low async reset), data_in (1 bit/cycle)
  Output : detected — high in the cycle the 4th bit of a match is received

Requirements:
1. Moore FSM with 5 states:
     S0: idle / no prefix matched
     S1: matched "1"
     S2: matched "10"
     S3: matched "100"
     S4: matched "1001" → detected = 1
2. Overlapping allowed — after S4, transition based on the KMP failure function
3. State register: always_ff with async reset to S0
4. Output: assign detected = (curr == S4)  — no latch

State transition table:
  State | in=0 | in=1
  ------+------+-----
  S0    |  S0  |  S1
  S1    |  S2  |  S1
  S2    |  S3  |  S1
  S3    |  S0  |  S4
  S4    |  S2  |  S1

Overlapping example:
  Input : 1 0 0 1 0 0 1
  Detect:         ^       ^   (detected=1 on bit 4 and bit 7)

Examples:
  "1001"    → detected on bit 4
  "1000"    → no detection
  "11001"   → detected on bit 5
  "1001001" → detected on bits 4 and 7

Interview follow-ups:
1. Why does S4 transition to S2 when data_in=0, rather than to S0?
   — "1001" + "0" = "10010". Its suffix "10" is a prefix of "1001", so transition to S2.
2. What is the difference between Moore and Mealy machines?
   — Moore outputs depend only on the current state. Mealy outputs also depend on
     the input and may respond one cycle earlier, but the circuitry is more complex.
3. How can the KMP failure function be used to derive state transitions?
   — Build the pattern's failure function. On a mismatch, fall back to the state
     corresponding to failure[j-1].
