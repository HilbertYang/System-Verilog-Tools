Question: Sum of Three Division Results

Implement the following unsigned operation:

  out = a / b + c / d + e / f

Parameters and interface requirements:
1. a, b, c, d, e, and f are DATA_WIDTH-bit unsigned values; DATA_WIDTH defaults to 16.
2. out is DATA_WIDTH+2 bits wide, enough to hold the sum of three maximum quotients.
3. Both input and output interfaces use valid/ready handshakes.
4. If a divisor is zero, treat the corresponding quotient as zero and assert
   div_by_zero=1 when the result is valid.
5. out and div_by_zero must remain stable while out_valid=1 and out_ready=0.

Implement both of the following architectures:

Architecture 1: Minimum Area (div_sum_area_min)
- Instantiate one unsigned_restoring_divider to calculate a/b, c/d, and e/f sequentially.
- Share one shift, compare, and subtract datapath across all three divisions.
- Use an accumulator to hold intermediate results.
- Each division takes DATA_WIDTH iteration cycles. The outer state machine also
  introduces cycles for starting operations and transferring results.
- This architecture has higher latency but requires only one iterative divider.

Architecture 2: Maximum Speed (div_sum_speed_max)
- Calculate a/b, c/d, and e/f simultaneously, inferring three parallel dividers
  during synthesis.
- Register the three quotients in the first stage. In the second stage, sum them
  with an adder tree and register the output.
- Both stages support valid/ready backpressure and can accept consecutive inputs.
- Once the pipeline is full and the downstream remains ready, throughput is one
  set of results per clock cycle.

Notes:
- The synthesis tool determines whether the RTL / operator maps to combinational
  logic, a pipeline, or a vendor divider IP.
- For strict maximum clock frequency requirements, replace the three / operations
  in the speed-oriented architecture with fully pipelined divider IPs of equal latency.
- Compiling the area-oriented architecture also requires
  IP/unsigned_divider/unsigned_restoring_divider.sv.
