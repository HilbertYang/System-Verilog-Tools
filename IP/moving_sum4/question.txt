# Verilog Interview Problem: 4-Sample Moving Sum

Design a synthesizable module that receives unsigned 8-bit samples and outputs the sum of the four most recently accepted samples.

## Interface

```systemverilog
module moving_sum4 (
    input  logic       clk,
    input  logic       rst_n,
    input  logic [7:0] in_data,
    input  logic       in_valid,

    output logic [9:0] out_sum,
    output logic       out_valid
);
```

## Requirements

- Use an **active-low synchronous reset**. Reset discards all sample history and clears `out_sum` and `out_valid`.
- Accept a sample on every rising edge with `in_valid=1`. There is no input backpressure, and the downstream is always ready.
- Do not produce a valid output until four samples have been accepted after reset. Keep `out_sum=0` until the fourth sample arrives.
- Immediately after the edge that accepts the fourth sample, assert `out_valid` and update `out_sum` to the sum of those four samples.
- For each later accepted sample, discard the oldest sample from the window and include the new sample. Update `out_sum` immediately after that same edge and assert `out_valid`.
- The window advances by one **accepted sample**, not by one clock cycle. Gaps in `in_valid` must not discard or alter stored samples.
- On an edge with `in_valid=0`, clear `out_valid` and hold `out_sum` unchanged.
- Consecutive accepted samples after the initial window must produce consecutive valid outputs. `out_valid` may remain high across consecutive cycles; each such cycle represents a new sum.
- Use unsigned arithmetic with enough width to represent the maximum sum, `4 x 255 = 1020`, without overflow.
- Use a running-sum approach to update the window sum as new samples arrive.
- Support one accepted sample and, after the initial window, one output per clock cycle.

## Example

Assume reset has completed. Inputs are sampled at the listed rising edges; outputs are shown immediately after each edge. All values are decimal.

| Edge | `in_valid` | `in_data` | `out_valid` | `out_sum` |
|---|---|---|---|---|
| 1 | 1 | 10 | 0 | 0 |
| 2 | 1 | 20 | 0 | 0 |
| 3 | 0 | Don't care | 0 | 0 |
| 4 | 1 | 30 | 0 | 0 |
| 5 | 1 | 40 | 1 | 100 |
| 6 | 1 | 50 | 1 | 140 |
| 7 | 0 | Don't care | 0 | 140 |

The first complete window is `[10, 20, 30, 40]`. The next window is `[20, 30, 40, 50]`.

## Task

Implement the module. Be prepared to explain the initial window, invalid-input gaps, how the oldest sample is identified, and the arithmetic widths used for updating the sum.
